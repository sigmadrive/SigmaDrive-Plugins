SigmaDrive 0.2.5 — 두 실제 PC 연결·공유 검증 절차
작성: 2026-10-15 / Windows x64 외부 검증용

배포
GitHub 릴리스: https://github.com/sigmadrive/SigmaDrive-Plugins/releases/tag/client-v0.2.5
설치 파일: SigmaDrive_0.2.5_x64-setup.exe
CDN 다운로드 도우미: SigmaDrive-Download-0.2.5.exe (GitHub 릴리스에서 받기)
정확한 jsDelivr 커밋 주소, 파일 크기, SHA-256은 위 릴리스의 안내와 SHA256SUMS.txt를 기준으로 확인한다.
이 문서는 공개 배포용이다. 계정, 개인키, 복구 키, 실제 초대 코드, 사용자 폴더 경로를 포함하지 않는다.

범위와 사전 조건
- Windows 10/11 x64 PC 두 대를 준비한다. 이번 패키지는 ARM64 Windows/macOS용이 아니다.
- 처음에는 같은 LAN, 다음에는 PC B를 모바일 핫스팟 등 다른 인터넷 회선에 연결해 반복한다.
- PC A는 폴더 제공자, PC B는 수신자다. 이후 역할을 바꿔 반대 방향도 확인한다.
- PC B에서 드라이브 마운트에 사용할 Dokany 2.x x64를 설치한다. 기존 실측 환경은 Dokan Library 2.3.1.1000이다.
  공식 배포: https://github.com/dokan-dev/dokany/releases
  드라이버 설치는 관리자 권한/재부팅이 필요할 수 있다. 이 시험 설치 파일에는 드라이버를 동봉하지 않는다.
- WebView2가 없으면 설치 프로그램이 Microsoft Evergreen bootstrapper를 내려받는다. 인터넷 연결이 필요하다.
- hosts 파일 수정, 사설 CA 설치, TLS 검증 해제는 필요 없다.
- TCP 443 outbound: console.sigmadrive.net, team.sigmadrive.net, meta.sigmadrive.net,
  share.sigmadrive.net, relay.sigmadrive.net, cdn.jsdelivr.net, raw.githubusercontent.com 및 로그인 제공자.
- STUN 별도 검증은 net.sigmadrive.net UDP 3478을 사용한다. TCP 접속 검사만으로 UDP/STUN 성공이라고 판정하지 않는다.
- 현재 팀 공유는 읽기 전용이다. 팀 공유 전송 성공과 NetBird/WireGuard 직접 터널 성공은 별도 결과로 기록한다.
- Authenticode 발행자 서명이 아직 없는 시험 릴리스다. 설치 전 릴리스의 SHA-256을 대조한다.
  서명된 배포 메타데이터 검증은 Windows 발행자 서명과 다르다. 보안 정책상 unsigned 실행이 금지된 PC에는 설치하지 않는다.

1. 설치와 로그인
1) GitHub 릴리스에서 설치 파일을 직접 받거나, CDN 다운로드 도우미를 받아 실행한다.
   도우미는 내장된 신뢰 루트와 서명 메타데이터를 먼저 검사하고 jsDelivr의 5개 조각을 받아 설치 파일을 도우미 옆에 저장한다.
   진행률·이번 수신량·재사용 조각·전송 원본을 표시한다. Ctrl+C로 중단 후 다시 실행하면 검증된 조각을 재사용한다.
   일시적인 전송 실패만 같은 커밋의 GitHub 보조 경로로 전환한다. 서명·해시 오류나 HTTP 403을 우회하지 않는다.
   jsDelivr의 EXE 직접 요청은 HTTP 403으로 거부됐으므로 CDN에서 EXE 하나를 직접 받는 링크는 제공하지 않는다.
   도우미는 설치를 자동 실행하지 않는다. 도우미도 Windows 발행자 서명은 없으므로 SHA256SUMS.txt와 먼저 대조한다.
   이 도우미의 서명 메타데이터 만료는 2026-10-22 08:17:31 KST다. 이후에는 새 도우미를 받거나 GitHub 설치 파일과 공지된 해시를 사용한다.
   PowerShell에서 설치 파일 해시를 확인한다.
   Get-FileHash -Algorithm SHA256 -LiteralPath "$env:USERPROFILE\Downloads\SigmaDrive_0.2.5_x64-setup.exe"
   파일명이 브라우저에 의해 달라졌다면 실제 저장 경로를 사용한다. 해시가 다르면 실행하지 않는다.
2) 기존 SigmaDrive 설치가 없는 PC에 설치하고 실행한다. 기본 설치 위치는 %LOCALAPPDATA%\Programs\SigmaDrive다.
   데이터는 %LOCALAPPDATA%\SigmaDrive에 분리된다. 기존 설치를 직접 덮어쓰려 하면 안전 검사로 차단된다.
   기존 개발/Update Pilot 설치가 있는 PC는 임의로 레지스트리나 DB를 지우지 말고 담당자에게 업그레이드를 요청한다.
3) 앱 버전 0.2.5를 확인한다. 회원가입·로그인 화면에서 서비스 주소가 https://console.sigmadrive.net인지 확인한다.
4) 본인 Google 계정으로 로그인한다. 약관/권한 동의는 사용자가 직접 확인한다.
   신규 PC는 아직 Google OAuth 데스크톱 앱의 Client ID/Client secret을 로그인 설정에 처음 한 번 입력해야 한다.
   서버 허용 목록에 등록된 시험용 앱 정보를 담당자로부터 별도 안전한 경로로 받는다.
   이 등록값은 설치 패키지나 이 공개 문서에 포함하지 않는다. Google 앱이 Testing 상태라면 수신자 계정도 테스트 사용자 등록이 필요하다.
   이미 연결된 계정을 사용하는 개발 PC와 달리 새 PC에서 이 단계가 생략되지 않는 점에 유의한다.
5) A는 설정 → 개인 프로필에서 로그인한 계정으로 온라인 프로필을 생성하거나 기존 프로필을 복원한다.
   기존 프로필이 있다면 새로 생성하기 전에 복원 여부를 결정한다. 복구 키는 본인이 별도 보관하고 채팅/보고서에 넣지 않는다.
   B는 받기만 할 때 온라인 프로필이 필수는 아니다. B도 폴더를 제공할 때는 본인 온라인 프로필이 필요하다.

2. PC 등록과 폴더 만들기
1) A: 파일 공유 → '공유 준비 확인·본인 PC 등록'. 로그인·온라인 프로필 검사를 통과해야 한다.
2) B: 파일 공유 → '회원으로 본인 PC 등록'. B도 제공자라면 준비 확인 버튼을 사용한다.
3) 두 PC의 '이 PC의 기기 확인 정보'를 열고 인증서 SHA256 지문을 별도의 신뢰할 수 있는 채널로 대조한다.
4) A에 새 시험 폴더를 만들고 일반 텍스트, 한글/공백 이름 파일, 하위 폴더, 20~100 MB 시험 파일을 넣는다.
   개인 자료 대신 새로 만든 시험 파일을 사용한다. 서로 다른 두 폴더를 만들어 다중 공유도 확인한다.
5) 탐색기에서 시험 폴더 우클릭 → 'SigmaDrive로 공유 / Share with SigmaDrive'.
   Windows 11에서는 '더 많은 옵션 표시' 안에 있을 수 있다. SigmaDrive 로고와 선택한 폴더가 표시되는지 확인한다.
6) 프로토콜은 SigmaDrive 팀 공유(sigma-api)를 선택하고 공유 이름/대상을 확인해 저장한다.
   S3 플러그인 설치는 이 팀 공유 시험의 선행 조건이 아니다. 하나의 프로토콜로 여러 폴더를 각각 공유할 수 있다.

3. 서로 다른 회원인 A와 B 연결
1) A: '공유 멤버와 수신자별 접근'에서 해당 공유의 '이 공유에 멤버 초대'를 누른다.
2) B에게 생성된 초대 코드를 별도로 전달한다. 코드를 공개 이슈/로그에 올리지 않는다. 코드 유효 시간은 24시간이다.
3) B: '받은 멤버 초대 코드' 입력 → '회원으로 초대 수락'.
4) A: 수락한 회원에 대해 '공유 멤버로 추가'. 초대 수락만으로 파일 접근이 승인되지는 않는다.
5) B: 공유 ID로 '읽기 신청'. A는 신청 기기를 확인하고 '지문 확인 후 승인'에서 B의 실제 인증서 지문을 대조해 승인한다.
6) B: '내 드라이브로 연결할 팀 폴더'의 '기기 확인 후 연결'에서 A의 실제 지문을 확인한다.
7) B에서 사용하지 않는 드라이브 문자(예: Y:)와 네트워크 드라이브 설정을 저장하고 연결한다.
   같은 회원을 두 PC에서 사용하는 경우에도 기기 지문 확인은 생략하지 않는다.

4. 합격 기준과 기록
- A에 '공유 중', B에 공유 드라이브 '연결됨', 탐색기에 드라이브가 보여야 한다.
- B가 하위 폴더/한글 파일을 열고 로컬 폴더로 복사할 수 있어야 한다.
- A 원본과 B 복사본에 각각 Get-FileHash -Algorithm SHA256을 실행해 해시/크기가 같아야 한다.
- B에서 공유 드라이브에 새 파일 쓰기, 이름 변경, 삭제를 시도하면 거부되어야 한다. A의 원본은 보존되어야 한다.
- A의 공유 중지 후 B에서 새 파일 열기/새 구간 읽기가 실패해야 한다. 이미 내려받은 사본은 남는 것이 정상이다.
- A가 다시 공유 시작하면 B에서 다시 연결하여 같은 해시로 읽을 수 있어야 한다.
- A의 '승인한 기기' → '승인 해제', 또는 신청 내역의 '접근 회수' 후 해당 B의 읽기가 차단되어야 한다.
  5초, 15초, 30초에 새 읽기를 확인하고 실제 차단 시간을 기록한다. 30초 후에도 새 읽기가 되면 실패다.
- A의 '멤버 접근 회수'는 같은 회원의 다른 기기에도 적용되는지 확인한다. 다른 허용 회원/다른 공유가 유지되는지도 확인한다.
- 두 공유 중 하나만 중지하면 나머지 폴더는 계속 읽혀야 한다.
- A 앱 창을 닫는 것은 트레이 숨김이므로 공유 중지와 같지 않다. 반드시 '공유 중지'로 시험한다.
- 인터넷 끊기/복구 후 상태 전이와 재연결을 확인한다. PC 절전/재부팅 후 자동으로 재개되는지, 명시적 재개를 요구하는지 기록한다.
- A의 온라인 프로필 일시 중지 또는 로그아웃 후 제공 중인 공유가 중지되는지 확인한다.
  다시 로그인/프로필 활성화 후 '검증하고 공유 재개'가 필요하면 직접 확인한다.
- 같은 LAN 결과와 다른 NAT/회선 결과를 별도로 적는다. UDP STUN 성공을 실제 파일 전송/직접 연결 성공으로 대신 기록하지 않는다.

5. Console 확인
https://console.sigmadrive.net/service-status 에서 팀 공유·STUN 등 서비스 상태를 확인한다.
공유 관리에서 기기 최신 보고 시각, 공유 상태/신청·승인·회수 기록을 확인한다.
공유를 모두 중지한 PC의 relay_connected=false/온라인 아님은 공유 서버 세션이 닫힌 정상 상태일 수 있다.
PC의 회원 보고 시각과 공유 상태를 함께 보고 서버 장애와 구분한다.

6. 추가 배포 시험과 정리
- 설정 → 다운로드/공유 프로토콜 관리에서 S3 선택 설치를 실행한다. jsDelivr/GitHub 보조, 진행률, 중지/이어받기를 확인한다.
- 조각 재개는 완료·검증된 최대 4 MiB 조각을 재사용한다. 진행 중이던 미완성 조각은 다시 받는다.
- MiniLM 모델은 배포 시험용이다. 설치만으로 한국어 의미 검색/인덱싱 검증이 완료되지는 않는다.
- 이번 신규 설치 패키지는 기존 Update Pilot과 제품 식별자가 다르다. 기존 Pilot용 자동 업데이트 피드에 이 설치 파일을 직접 승격하지 않는다.
  Authenticode 발행자 서명과 일반 설치본의 업데이트 설정 프로비저닝/이전 경로는 후속 작업이다.
- 종료 시 B에서 드라이브 연결 해제·공유 수락 취소, A에서 공유 중지·시험 권한 회수를 수행한다.
- 제거 시험은 먼저 공유를 중지한다. Windows 설치된 앱에서 SigmaDrive를 제거한 뒤 탐색기 우클릭 메뉴/로고가 사라졌는지 확인한다.
  원본 파일과 사용자 데이터 보존 여부도 확인한다. 이 문서는 두 실제 PC의 완료 결과가 아니라 실행할 검증 절차다.

결과표에 남길 항목
일시 / A·B 앱 버전 / Windows 버전 / Dokany 버전 / 같은 LAN 또는 다른 회선 /
공유 ID / 송수신 바이트 / SHA-256 일치 / 읽기 전용 / 중지·재개 / 기기·회원 회수 /
재접속·재부팅 / Console 상태 / 오류 코드 / 차단까지 걸린 초 / 최종 정리 여부.
계정 암호, OAuth secret, 토큰, 초대 코드, 복구 키는 결과표에 기록하지 않는다.
